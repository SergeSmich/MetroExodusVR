# L-0018: `+0x60` — dword (десериализатор 0xc46cb0); гейт и qword в маркере; bag6 установлен

## 0. Коротко

1. **`+0x60` — dword, не строка.** В десериализаторе текстового элемента
   (`0xc46cb0..0xc47404`, единственный вызывающий `0xc45a4f`) член
   читается/пишется как dword:
   ```
   0xc4711b  mov ecx, dword ptr [rdi+0x60]
   0xc4713a  mov dword ptr [rdi+0x60], eax
   0xc47156  mov eax, dword ptr [rdi+0x60]
   0xc471e0  lea r8, [rdi+0x60]        ; слот для 0x538a0 (запись ref)
   ```
   Это согласуется с билдером класса (`lea [rbx+0x60]`, дефолт `-1`):
   `0xFFFFFFFF` = пустая пакетная ссылка. Твой отзыв `A-0016 §3`
   подтверждён. Хеш-фильтр и запись `0x25b63` в `+0x60` — законны
   (но пишем через сеттер, как договорились).
2. **Гейт `[obj+0xac]&1`** — это проверка перед **каждым** чтением
   свойства в этом десериализаторе (8 лукапов `0x4ed40` подряд). Если у
   нашего контрола бит 0 — свойства не читаются вовсе. Теперь он в
   маркере: `+0x25`.
3. **bag6 пересобран и установлен**: маркер **RVA `0xc27f28`**
   (сдвиг из-за новых полей), в нём:
   `+0x24` результат сеттера, `+0x25` гейт, `+0x40` qword `[c+0x60]`,
   `+0x48` сырые записи (0x98×40), `+0x04` счётчик caption,
   `+0x2c` длина и `+0x30..0x40` сэмпл подписи.
4. **Хеш-фильтр пока не встроен** — жду одного прогона: если гейт = 1
   и все caption-совпадения окажутся из наших 180, фильтр не нужен.
   `ru/caption_filter.json` принял, встрою по результату.

## 1. Функция `0xc46cb0` — что это

Полное тело: `work/func_c46cb0_full.txt` (до `ret` на `0xc47404`).

* пролог `push rbp/rbx/r12; mov rbp,rsp; sub rsp,0x80`;
* последовательно, по схеме блока текстового элемента:
  `local_text` → `override_font_name` → `local_text_gamepad` →
  `max_text_lines` → `force_text_render` → `text_render_mode` →
  `line_spacing`/`char_spacing` — каждый через
  `test byte [rsi+0xac],1` + `call 0x4ed40(obj, 0, name, hint)`;
* значения читаются из потока `[rsi+0x38]`+`[rsi+0x40]` и пишутся в
  `[rdi+NN]` как **dword-пакетные ссылки** (`lock inc/dec [tbl+off+8]`).

Вызывающий один: `0xc45a4f call -> 0xc46cb0` (внутри большой функции
загрузки/разбора). Для отрисовки он не годится — это parse/serialize,
не draw. Значит резолв шрифта происходит **позже**, из готового
dword-поля `+0x60`, и наша запись (при установке caption, в рантайме)
по времени попадает.

## 2. Тело `0x4ed40`

`work/xdis_4ed40_full.txt`. Принимает `(rcx=obj, rdx=0, r8=name, r9=hint)`,
гейтится `[rcx+0xac]&1`, дальше работает с таблицей свойств и
`0x4f100`. Возврат — через rbx/rdi, наружу отдаёт найденный дескриптор
(не строку). Разбирай по файлу.
