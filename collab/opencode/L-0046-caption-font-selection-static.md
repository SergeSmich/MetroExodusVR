# L-0046: кто выбирает шрифт для подписей страницы VR (латиница вместо кириллицы)

## Короткий итог

Объектная сторона уже корректна: текстовые объекты подписей ссылаются на кириллические
ресурсы, а на экране всё равно `DOH5` / `OH5nD@5`. Значит латинский шрифт подставляет
не текст и не `fonts_ru.bin`, а слой отрисовки. Нужен статический ответ: где в EXE
выбирается шрифт для caption-классов и где стоит fallback на `arial`.

## Новые факты этого прогона (0.9.2, pid 24020)

1. Хэндлы имён (через пул `EXE+0x175F140`): `regular` = **0x17056f48**.
   В L-0044/L-0045 указан 0x17056d38 — это ошибка: там длина 1 и мусорный байт.
   `menu` = 0x001c58b0, `main_menu` = 0x000d8450, `typewriter` = 0x00455b20.
   `arial` = 0x17056e30 даёт длину 28781, т.е. это не имя — хэндл другого вида.
2. Поле `+0xC0` объекта строки = `float scale | dword name-handle`:
   * подписи страницы: `0x3d200000_17056f48` (scale 0.039, имя `regular`);
   * строки меню: `0x3d200000_001c58b0` и `0x3d855556_001c58b0` (имя `menu`).
3. `[obj+0xC8] → [style+0x58]` в живом процессе даёт именно кириллицу:
   подписи → `font\font_font_regular_cyr_ru` (269 записей),
   меню → `font\font_metro_for_menu_cyr_ru` (269 записей).
4. `tools/font_table.py --list work/fonts_ru.bin`: `menu`, `main_menu`, `regular`, `map`,
   `typewriter` → кириллические ресурсы, 271 запись, ink 238–243.
   `fonts_us.bin` — 203 записи, латиница. Штатный поиск по алиасу латиницу не объясняет.
5. В объекте подписи (первые 0x1e8 байт, шаг 8) **нет ни одного поля**, равного живому
   `arial`-объекту (0x1d1a0ac1638): рисующий слой берёт шрифт не из объекта строки.
6. Зануление записи глифа 0x44 во всех 31 живом Font-объекте (`work/blank_page.py`) не меняет
   ни одного пикселя полосы подписей (шум 0) — рисование идёт из запечённого атласа
   или из Font-объекта, который мой сканер не видит.

## Задачи

**T1 (главная, статика).** Найти в MetroExodus.exe:
* загрузчик `fonts_*.bin` и место, где выбирается `us`/`ru` таблица для меню и для
  caption-классов (xref на строки `fonts_us`, `fonts_ru`, `content\scripts\fonts_`);
* место, где имя-хэндл (`regular`/`menu`) превращается в `Font*`, и где стоит fallback
  на `arial` (строка `font\font_arial`): RVA, цепочка вызовов, что лежит в регистре;
* что такое таблица по RVA `0x1733240` (слоты +0x04 `regular`, +0x08 `arial`,
  +0x0C `menu`, +0x10 `console`) — список хэндлов, кэш `Font*` или дефолты, кто её читает.

**T2.** По результату — `tools/patch_caption_font.py --dll MetroExodusVR.dll --rva … --bytes …`
с бэкапом и `--revert`, чтобы я применял патч на копии DLL и проверял снимком в игре.

**T3.** Когда пришлю выгрузку `work/rec_diff.py` (по-DWORD дифф 0x1e8-записи подписи против
нативного `$back`-хинта, который рисует кириллицу) — указать, какие поля реально участвуют
в выборе шрифта на кадре.

**T4.** `ru/ENCODING_NOTES.md` §11 «механизм выбора шрифта для подписей» + список закрытых
гипотез (тип контейнера `+0xD0`, `+0x58/+0x50/+0x60/+0xC0`, подмена имён `*_ru`, UTF-8/Latin-1,
правка tcmap без атласа, зануление живых глифов, подмена живых `$back`-хинтов).

## Почему это не data-фикс

`fonts_ru.bin` уже указывает `menu`/`regular` на кириллицу (п. 4), а экран латинский.
Остаются два варианта: для этого слоя грузится `fonts_us.bin`, либо fallback жёстко `arial`.
Оба лечатся только в DLL — redirect загрузки таблицы или подмена fallback-имени.

## Критерий готовности

Есть RVA + байты (или порядок hook'а), после которых в VR на странице ИГРА/ГРАФИКА подпись
`TURN MODE` рисуется кириллицей, а не `DOH5` / `OH5nD@5`.

## Ограничения

Игру не запускать (она у меня и требует HMD/ручного открытия экрана), EXE не патчить,
в `collab/` только текст. Ответ — новым `A-*`, не правкой этого файла.
