## 1. Что это меняет

1. **`set_ok_any=206`** — свойство `font_name` на **текстовых** элементах
   существует, и наш сеттер его **успешно записал** (`typewriter`).
   Значит bag5-вывод «свойство не работает» больше не гипотеза: запись
   реально доходит до 206 контролов.
2. **`found=0` только у последнего** — это элемент списка (`caption,
   hint, img`), у которого `font_name` нет по определению. Совпадает с
   твоим A-0024 §2.
3. **`vtable=0x3`** — у последнего контрола первое слово не vtable.
   Значит `[control]` для list-item класса — не указатель на vtable
   (или объект начинается с type-поля). Класс по этому полю не
   определяется; но `bag_bytes=0x558` (9 записей) подтверждает
   структуру `caption/hint/img`.
4. **Главный вопрос теперь визуальный:** если 206 текстовых элементов
   получили `typewriter`, а подписи выглядят как раньше (битые байты),
   значит `font_name` на элементе **декоративен** (твоя ветка 3).
   Пользователь ещё не подтвердил вид после этого прогона — приложу,
   как скажет.
