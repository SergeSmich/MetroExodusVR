# Кодировка текста мода: текущее состояние разбора

Документ фиксирует, что уже доказано и где именно застряла локализация.
Нативные строки игры переводятся и отображаются корректно; проблема — только
у строк, которые рисует сам мод.

## Что работает

* Перевод применяется к бинарному релизу: в PE добавляется секция `.ru`
  (RVA `0xbcc000`), сайты `lea reg,[rip+literal]` перенаправляются на новые
  строки, inline `std::string` заменяются `jmp`-стабами.
* ASCII-валидаторы ослаблены (`cmp al,0x5e` -> `cmp al,0xff`):
  `0xa1816`, `0xa30f6`, `0xa12c8`, `0xa12c6`.
* Установка пишет бэкапы `.orig` и пиннит версию: `updater.json`
  (`mode=never`, `pinned_version=0.9.0`).
* В игре строки действительно подменяются, нативные подписи
  (`НАЗАД`, `ВКЛ`, `Прокрутка`) остаются корректными во всех сборках.

## Что не работает

Байты, которые мод отдаёт в UI, интерпретируются таблицей, совпадающей с
**US-charmap** (из `stable_us.lng`): 203 записи в порядке частоты глифов.

```
US[0x29]='D'  US[0x2c]='E'  US[0x35]='B'  US[0x45]='4'
US[0x37]='P'  US[0x40]='J'  US[0x50]='/'
```

Отсюда наблюдаемый мусор: `SNAP TURN ANGLE` -> `DBEF 4...`,
`ВКЛ` (индексы RU-charmap `0x37,0x40,0x50`) -> `PJ/`.
Кириллицы в US-charmap нет вообще; RU-charmap содержит 271 запись,
из них 67 кириллических (`RU[0x37]='В'`).

## Проверенные и отброшенные кодировки

| Кодировка | Результат в VR |
|---|---|
| CP1251 | пустые подписи, tofu в описаниях |
| UTF-8 | `.notdef` на каждый байт |
| `.lng` compact-индексы (`idx<0xE0` -> 1 байт, иначе `v=idx+0xDE41`, `b=v/255`, `r=v%255`) | латинский мусор по US-таблице |

## Карта кода

| RVA | Что это |
|---|---|
| `0x80ebf0` | глобал страницы VR-настроек |
| `0xb4290` | конструктор страницы |
| `0xb4cb0` | ленивый getter (вызывает билдер) |
| `0xb0b50` | билдер страницы (пишет записи `string_view`) |
| `0xb4d60`, `0xb7210` | потребители getter'а |
| `0x480540` | `lea rcx,[0x80ebf0]; jmp 0xb4290` (статический ctor) |
| `0x4c5648` | `GlyphAtlas` |
| `0x4c7360` | `text node draw` |
| `0x51a743` | `[links] no font resource {}; ImGui's own instead` |
| `0x18a7a0..0x18abcd` | glyph-хуки |

Записи страницы: `{key ptr/len @+0x00/+0x08, label ptr/len @+0x10/+0x18, ...}`;
строки создаются `0x2a8c0`/`0xa7d90`/`0xa7df0` **без конверсии кодировки**.

## Гипотеза

Текст мода рисуется шрифтовым ресурсом/атласом с US-charmap, а не через
языковой путь локализации игры. Варианты фикса:

1. переключить ресурс/таблицу на RU-вариант и кодировать перевод индексами
   RU-charmap;
2. найти узкую->Unicode конверсию (таблица 256 codepoints,
   `MultiByteToWideChar`, глобальный charset) и заставить её декодировать
   наши байты;
3. пройти по wide-string пути.

## Ограничения патча

* inline `std::string`: длина <= `0xF` (SSO);
* `string_view`: <= `0x7E`; подпись 1..`0x3E`;
* общие литералы (`OFF`, `TAA`, `DLSS`, `FSR`) не трогаем — только
  редиректы в сайтах мода;
* ImGui-слой (метрики, отладка, dev-хоткеи) не переводится, кириллица в
  ImGui не требуется;
* файлы игры не изменяются — только `MetroExodusVR.dll`.
