# L-0037: `font_name` — no-op, подмена слота `arial` — no-op, в контейнере подписи нет ни ссылки на `arial`, ни шрифта

## 1. Что проверено в игре (три сборки 0.9.1, charmap, `--caption-all`)

Страница мода (`mevr_settings`, строка списка): наши подписи нарисованы
латиницей, байт-в-байт как предсказывает §9: `ИГРА→DOH5`,
`ГРАФИКА→OH5nD@5`, `ДВИЖЕНИЕ→C7Dcl3DI`, `ОРУЖИЕ→?HJcDI`. Игра при этом рядом
рисует свои строки кириллицей нормально (`ESC НАЗАД` внизу справа, левая
колонка категорий) — то есть шрифт игры в RU рабочий, отличается только наш
текст.

### 1.1 `--caption-font menu` (запись `font_name` в контейнер)

Сборка `work/MetroExodusVR-0.9.1-ru-charmapmenu.dll` (`279F55BD…`),
лог `2026-11-12_003828_hook_36804.log`, маркер `0xBFB05C`:

```
set_calls 259   set_ok 245   set_fail 0   set_last 1
29 menus loaded (3 replaced, 26 new), 221 captions set
refused: ровно 1 (mevr_reload_pouch)
```

Сеттер **принял** `font_name = 'menu'` для 245 объектов, и **на экране ничего
не изменилось**: те же `DOH5`/`OH5nD@5`.

### 1.2 Подмена слота `arial` в реестре шрифтов

Сборка `work/MetroExodusVR-0.9.1-ru-swap.dll` (`238F69DB…`, без
`--caption-font`, только `--swap-arial-sticky`), маркер `0xBFB08C`:

```
swap_fixes 1        (слот +0x08 действительно переписан arial -> menu)
set_calls 0
```

Экран **не изменился**. Значит отрисовка не берёт шрифт из слота реестра
в момент кадра — указатель на шрифт уже разрезолвлен раньше.

### 1.3 Поиск ссылки на `arial` внутри контейнера (`--font-subst write --ctl-dump`)

Сборка `work/MetroExodusVR-0.9.1-ru-probe.dll` (`B84402FE…`), маркер
`0xBFB43C`, лог `2026-11-12_011823_hook_31156.log`:

```
set_calls 259  set_ok 245  set_fail 0
subst_ctls 259   subst_found 0   subst_first -1   subst_last 0   subst_noref 0
static_done 1    ctl_flags 1     (бит1 = local_text — НЕ выставлен ни разу)
```

`subst_found = 0` на 259 объектах: **ни один dword в `[control, control+0x100)`
не равен ссылке на `arial`**. Дамп самого объекта (последняя подпись —
`mevr_vr`):

```
+000 0x0000020ddcbb6503          +008 SSO std::string "mevr_vr"  (+018 len=0x0b, +020 cap=0x0f)
+030 0x000000f5214869f2          +038 0x20fe83171c0   +040 0x20fe8318980   +048 0x20fe8318980
```

Это **контейнер свойств** (SSO-строки), а не UI-контрол: ни ссылки на шрифт,
ни указателя на объект шрифта в нём нет. `ctl_flags` бит1 не выставлен —
мод вообще не пишет `local_text`, поэтому «рабочего» образца того же сеттера
у нас нет.

### 1.4 Реестр шрифтов в рантайме

`--ctl-dump` в том же прогоне:

```
FONTS_PTR 0x7ff7ad1e3240
regular node 0x20ded2ce118 rc=365  arial 0x20ded2ce210 rc=2
menu    node 0x20de39e0c30 rc=1469 console 0x20decdeaa08 rc=332
```

Скан всего образа загруженной DLL на указатели на эти четыре узла: попаданий
нет, кроме нашего же маркера (`0xbfd4bc…0xbfd57c` = `marker+0x2080`). То есть
DLL **не кэширует** узел шрифта в своих глобалах.

## 2. Что из этого следует

1. Маршрут «свойство `font_name` в контейнере» закрыт окончательно: запись
   проходит (`set_ok=245`), объект — bag без шрифтового поля, отрисовка его не
   читает. Это согласуется с `A-0024 §2` и снимает `A-0033 §…` (ref-to-object
   больше некуда писать: в контейнере нет ни одного dword со ссылкой).
2. Маршрут «подменить слот в реестре `Fonts`» тоже закрыт: подмена применяется
   (`swap_fixes=1`), но шрифт на кадре берётся не из слота.
3. Остаётся ровно одно место, где может лежать шрифт: **путь отрисовки
   элемента списка**. Ни класс, ни контейнер мы туда не дотягиваем.

Дополнительно к статике: строки подписей мода лежат в DLL пулом
`file 0x4be600..0x4be8e0` (`MOVEMENT … mevr_vr`, рядом пары
`caption`/`id`), имена классов мода — `m3_main_*` в `file 0x4bccf0..0x4bcf00`.
Литерала `arial` в DLL **нет ни одного** (0 вхождений), имени шрифта рядом с
пулом подписей тоже нет. То есть шрифт подписей нигде в данных мода не
записан — он приходит из кода/класса игры.

## 3. Вопросы (по приоритету)

**Q1 (главный).** Найди в 0.9.1 функцию, которая рисует текст **элемента
списка** (тот путь, что обслуживает подписи мода; `A-0024` называет его
`on_draw_item`). Нужно:

* откуда она берёт шрифт: глобальный дефолт (`arial`), контрол списка, класс
  элемента, что-то ещё?
* точное место (смещение от объекта / RVA), где лежит **указатель на объект
  шрифта**, использованный в этот кадр. Если это глобал — RVA глобала.
* читает ли она текст как `char*` (байт → индекс в таблице, §9) или как
  `wchar_t*`/UTF-16 (кодпоинт → глиф)?

**Q2.** Если путь оказался **Unicode**: какой именно формат ожидается в
`caption` (UTF-8 или UTF-16 в `string_view`) и можно ли положить туда
кириллицу, не меняя шрифт? Тогда `--encoding utf8` надо перепроверить с
рабочим шрифтом: прошлый прогон был на `arial` и потому дал пустоту — он не
различает «декодер не тот» и «в шрифте нет глифа».

**Q3.** Если шрифт — глобал, захваченный при инициализации мода: скажи
файловое смещение этого глобала в DLL, чтобы переписать его на узел `menu`
**до** загрузки меню (тогда кэш уже не помешает).

**Q4.** Если шрифт берётся из класса элемента: назови класс строки
`mevr_settings` (в `mhs_classes.json` его нет — там только игровые классы) и
его поле `font`. Если поле пустое — вот и причина: пустое имя резолвится в
дефолт `arial` (§9), и тогда починка — вписать `menu` в это поле класса.
