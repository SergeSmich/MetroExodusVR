# L-0016: bag6 готов — хук пишет `override_font_name`, маркер несёт сырые записи

## 0. Коротко

1. **Вариант B (`[theme+0x6b0]`, тема-глобально) принят как отвергнутый
   окончательно** — по твоему §5: инверсия кодирования непереведённых
   общих литералов (`FSR`→`Э"p`, `DLSS`→`ИЗ""`) делает его гарантированным
   мусором на странице графики. Не берём.
2. **Собран `bag6`** = прежний перевод + твой §7.2: хук при установке
   `caption` пишет `"menu"` в **`override_font_name`** (тот же stringz-путь
   `0x9bc70`), а не в `font_name`. Команда:
   `--caption-font menu --caption-prop override_font_name`.
3. **Маркер вырос: `0x600 → 0x1C00`**. Вместо компактных 15-байтовых
   записей хук копирует **сырые записи verbatim, stride 0x98, до 40**
   (`+0x40..+0x18A0`). Заголовок прежний: `+0x08` контрол, `+0x10/+0x18`
   begin/end, `+0x20` число записей, `+0x28` caller.
   В каждой сырой записи kind лежит по `+0` → **kind-2 vs kind-1
   различимы прямо в копии** (и мы уже знаем: сеттер пишет только в
   `kind==1`, `cmp byte [rbx],1` @ `0x9bcde`).

## 1. Механика bag6

```
hook при name=="caption":
  marker[+1] = 1  (caption match)
  nested set(control rbx, "override_font_name" (len 0x12), "menu" (len 4))
       → site 0x9bc70 сам ищет запись (kind==1) по вектору [rcx+0x38..0x40]
  marker[+2] = результат al; [rcx+8..+0x28] = header-контекст
  копия bag[begin..end) — 40 × 0x98 сырых записей → marker+0x40
```

Детали копии:
* перед `rep movsb` стоит `cld`; rsi/rax продвигаются согласованно
  (баг «бесконечный цикл» поймал на дизасме и исправил);
* SSO-байты хранятся inline в копии — офлайн читаемы;
* heap-указатели указывали на живые строки только в момент копии, баг
  освобождён после load → офлайн парсер помечает их `[dead]`.

## 2. kind-1 vs kind-2 в сырых записях (твой §7.2-проверка)

Копия содержит поле kind → различие видно без пересборки:
* kind==2 (`override_font_name`+`choose`) — заголовок, value пуст;
* kind==1 (тело) — value это дефолт `''`.

В новом маркере это читается напрямую; специально отдельного поля не
добавлял — kind уже в байте `+0` каждой записи.

## 3. Живой план (следующий запуск игры)

1. Закрыть игру → установить `bag6` (`versions/0.9.0/MetroExodusVR.dll`).
2. Запустить, зайти в мод-меню (страница с нашими подписями).
3. `work/dump_bag.py 0xc27ed8` (новый формат):
   * `set_ok` — вернул ли вложенный сеттер успех для `override_font_name`;
   * есть ли вообще запись `override_font_name` kind==1 в копии;
   * `calls/caption` счётчики и переданное значение.
4. Если `set_ok=1` и запись нашлась — проверить в VR, стала ли подпись
   кириллицей (критерий: `РЕЖИМ ПОВОРОТА` вместо `TURN MODE`).
5. Если `set_ok=0` и записи нет — значит баг контрола мода не несёт
   `override_font_name`, и мы смотрим альтернативный путь.
