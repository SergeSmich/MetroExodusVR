# L-0034: портировать тулинг на 0.9.1 — charmap-энкодер + хук шрифта подписей

## Задача

Две вещи, без которых opencode не может проверить подписи в VR:

1. **charmap-энкодер для 0.9.1.** Кит `work/handoff091/MetroExodusVR_RU_v0.9.1_TEST/tools/apply_ru.py`
   умеет только `--experimental-cp1251` и без него отказывается собирать
   (`no encoding path is runtime-confirmed`). CP1251 в VR отклонён (L-0032).
   Нужен путь кодирования по таблице шрифта (`ru/charmap.txt`), как в 0.9.0-скрипте:
   `load_charmap()` / `encode_text()` — глиф = `шрифт.таблица[байт]` (модель A-0029).
2. **`build_caption_font_hook` под 0.9.1** — перенос пещеры из `tools/apply_ru.py`
   (0.9.0) на 0.9.1, с **записью** свойства шрифта на наших подписях
   (positive filter по FNV-1a, как сейчас), а не read-only проба.

## Контекст

### Адрес сайта

Сеттер 0.9.1 — **`0x9F0D0`** (0.9.0 — `0x9BC70`). Проверено локально
(`work/tmp_diff_setter.py`): нормализованный дизасм 0x700 байт от входа,
**591/591 инструкций совпали**, включая пролог
`push rbx/rbp/rdi/r14/r15; sub rsp,0x20; mov rbx,[rcx+0x38]; mov rbp,[rcx+0x40]`.
Значит раскладка control та же и смещения пещеры (`0x1C24`, `0x1C28`, `0x1C30`,
`0x1C4C`, `0x1988`, `0x1C60`, `0x1C64`, `0x1C6C`, `0x1A34`) переносятся без правок.

### Баг, который уже исправлен — не утащи его в порт

Коммит **`4ac6565`** (`local/opencode`, `git show 4ac6565`): восемь мест
`mov qword [reg+disp32], imm32` собирались как `opcode + disp32 + b"\0" * 8`.
Инструкция 11-байтовая, лишние два нуля исполнялись как `00 00`
(`add [rax], al`) → краш `write to 0000000000000065`,
`MetroExodusVR.dll+0xBD39D4`. После фикса (`b"\0" * 4`) пещера даёт
0 инструкций `add byte ptr [rax], al` при дизассемблировании.

### Что показал VR на 0.9.1 (L-0032)

`cand-bytecmap` (CP1251): **значения** меню по-русски, **подписи** пустые,
строка-подсказка в квадратиках. То есть байт-код перевода верный, а шрифт
подписей — не тот, чьей таблицей мы кодировали.

### Вопрос, который надо решить в этой задаче

Писать на подписи `font_name` или `override_font_name` — и через сеттер
`0x9F0D0` (штатный путь, `lock inc` на записи), а не сырой `mov` в
`[control+0x60]`. В 0.9.0 оба варианта собраны (`--caption-prop`), но
визуально ни один ещё не проверен: прогон 0.9.0 упал на HDR10 раньше, чем
дошёл до меню (см. ниже).

## Ограничения

* **Бинарники в git не кладём.** Отдавай только исходники `tools/**`;
  сборку DLL и VR-проверку делает opencode.
* Не трогать 0.9.0-путь (`tools/apply_ru.py`, адреса `0x9BC70`, `strings.tsv`) —
  он рабочий.
* Хук должен писать шрифт только на подписях из нашего фильтра, чужие строки
  не трогать.
* Новый файл лучше отдельным: `tools/apply_ru_091.py`, чтобы два пути не
  конфликтовали.

## Критерий готовности

1. `python tools/apply_ru_091.py --src <0.9.1 orig> --out X --no-fonts --verify`
   → `verify ok`, **без** `--experimental-cp1251`, текст кодируется по charmap.
2. С `--caption-font menu --caption-prop override_font_name` скрипт печатает
   RVA пещеры и `setter 0x9f0d0 redirected`, затем `verify ok`.
3. Дизасм пещеры: **0** инструкций `add byte ptr [rax], al`
   (нет осиротевших `00 00` после `mov qword [reg+disp32], imm32`).

## Вопрос

Есть ли у тебя сама DLL 0.9.1 для сверки адресов? Если нет — скажи, opencode
отдаст таблицу `RVA / строка / lea-сайт` отдельным TSV в `collab/`, без бинарника.

## Почему это не делает opencode

`tools/**` — зона Arena по AGENTS.md §3, и вся работа статическая: ни игра,
ни шлем для неё не нужны. У opencode наоборот: он может только собрать и
посмотреть в VR, а порт адресов и энкодера — это как раз то, что делается
по дампам.
