# Строки модской страницы рисует ImGui 1.92.8 — charmap-модель неверна

## Решение в двух строках

Текст модской страницы (Options → VR, подсказки, попапы) рисует **ImGui
1.92.8 из четырёх TTF, вшитых в DLL мода**. ImGui ждёт **UTF-8**; кириллицы
в этих TTF нет. Значит фикс — не charmap и не смена имени шрифта, а:

1. `apply_ru.py` пишет строки в **UTF-8**;
2. `merge_cyrillic.py` вкладывает кириллицу в четыре RCDATA-шрифта;
3. `apply_ru.py --fonts` (подмена RCDATA) становится **обязательной частью
   сборки**, а не «плашкой».

Это переопределяет `ru/ENCODING_NOTES.md` §1–4 и `docs/OPENCODE_START.md`
§2/§5 («движок не декодирует», «не трогать ImGui/TTF»). По `AGENTS.md` §7
приоритет у факта: модель ниже воспроизведена в игре и подтверждена по DLL.

## Чем доказано

| # | Факт | Где |
| --- | --- | --- |
| 1 | В DLL есть версия ImGui `1.92.8` | строка в `.rdata` |
| 2 | Мод грузит 4 RCDATA-шрифта: `INFO_BARLOW_CONDENSED_SEMIBOLD`, `INFO_INTER_MEDIUM`, `INFO_INTER_REGULAR`, `INFO_INTER_SEMIBOLD` | таблица ресурсов, lang 1033, type 10 |
| 3 | Загрузчик: `RVA 0x29ab60` заполняет поля объекта `+0x3d8/+0x3e0/+0x3e8/+0x3f0`; хелпер `RVA 0x297640` = `FindResourceA(type=10)` → `SizeofResource` → `LoadResource`/`LockResource` → `AddFontFromMemoryTTF` | дизассемблер |
| 4 | Лог-строка мода: `[links] no font resource {}; ImGui's own instead` | файловый офсет `0x519138` |
| 5 | Имена шрифтов лежат рядом, офсеты `0x519170`… — это таблица, а не литералы в коде | файл DLL |
| 6 | Все 4 TTF — **латиница**: 0 из 30 кириллических символов перевода в `cmap` | fontTools |
| 7 | `SizeofResource` даёт размер, хардкода нет → новый TTF может быть больше исходного | п.3 |
| 8 | ImGui 1.92: атлас динамический, `ranges` набор глифов не ограничивают → достаточно добавить глифы в TTF | `imgui_draw.cpp` 1.92.8 |

Размеры/адреса исходных ресурсов (для сверки после сборки):

```
INFO_BARLOW_CONDENSED_SEMIBOLD  size=109428  rva=0xb6ef88
INFO_INTER_MEDIUM               size=66992   rva=0xb89b00
INFO_INTER_REGULAR              size=66912   rva=0xb9a0b0
INFO_INTER_SEMIBOLD             size=67144   rva=0xbaa610
```

## Почему это объясняет все три прогона

| Прогон | Байты в `.ru` | Что видно в VR | Причина |
| --- | --- | --- | --- |
| CP1251 | `0xCF 0xF0 ...` | пустые подписи/тофу | для ImGui это невалидный UTF-8 — рисовать нечего |
| charmap-индексы | `0xE3 0x..` (compact) | латинский мусор, `ВКЛ` → `PJ/` | ImGui декодирует пары как UTF-8 → латинские кодпоинты |
| UTF-8 | `0xD0 0x92 ...` | `.notdef` на каждой букве | UTF-8 корректен, но в TTF нет кириллических глифов |

Во всех трёх случаях латинские части строк оставались читаемыми — это и есть
подпись декодера ImGui, а не таблицы символов шрифта.

## Что это меняет в плане

`A-0002` («найти имя шрифта и переключить на `_ru`») закрывается как
**неактуальная**: имени нет, шрифты — фиксированные RCDATA-ресурсы мода,
переключать нечего, надо вкладывать глифы. `A-0001` в части «имя шрифта из
пакета меню» тоже снимается; таблица ресурсов из п.1 приложена выше.

Что делает opencode (файлы `tools/apply_ru.py`, `tools/merge_cyrillic.py`):

1. `ENCODING = "utf-8"` по умолчанию, `--encoding utf-8|charmap|cp1251`
   (charmap/cp1251 остаются для отката и сравнения);
2. `--fonts` включён по умолчанию, `--no-fonts` — откат; проверка
   «4 ресурса найдены ровно по одному» уже есть в `collect_fonts()`;
3. `check_encodings()` и `report_limits()` считают **байты UTF-8**, а не
   символы; лимиты: SSO `0xF`, `string_view` `0x7E`, подпись `0x3E`,
   описание `0x7E`;
4. `merge_cyrillic.py`: доноры — Inter 4.001 (OFL) для трёх Inter и
   Roboto Condensed SemiBold (Apache-2.0) вместо Barlow Condensed (его
   свободного кириллического аналога нет); проверка 30/30 по `ru/*`;
5. сборка → структурная проверка 4 ресурсов в готовой DLL (fontTools) →
   `install_ru.py --force` → прогон в VR → `collab/runs/L-0001.json`.

Бюджет длин уже проверен: inline-`std::string` сайтов 23, **ни один** перевод
в UTF-8 не превышает `0xF` (максимум по всем строкам — 52 байта < `0x7E`).
То есть 2× рост от UTF-8 ничего не ломает.
