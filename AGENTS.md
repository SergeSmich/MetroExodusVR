# AGENTS.md — рабочий протокол для двух агентов

В этом репозитории над переводом работают **два агента одновременно**:

| Агент | Где живёт | Сильные стороны | Слабые стороны |
| --- | --- | --- | --- |
| **Arena** (браузерный) | облачная песочница, свой клон репозитория | статический анализ кода/дампов, написание инструментов, работа с PE/`.lng`, длинные рассуждения | **нет игры**, нет VR, нет Windows, нет сети к GitHub release-ассетам, не может ничего запустить в игре |
| **opencode** (локальный) | ПК пользователя | **есть игра и VR-шлем**, есть `MetroExodusVR.dll`, Steam, Windows, может собрать патч и проверить в игре | короткий контекст, дорого держать длинный разбор, легко потерять контекст между сессиями |

Ни один из них не может сделать задачу целиком: Arena не видит результат в
игре, opencode не должен заново выводить карту кода. Поэтому всё общение —
**через git**, а не через чат.

---

## 1. Три канала связи

### 1.1 Ветка `arena/<id>` — код (только Arena пишет)

* Arena коммитит и пушит **только** в свою ветку `arena/…` (её имя выдаётся
  сессии и не меняется).
* opencode **никогда не коммитит в `arena/…`**. Он читает её и делает
  `git fetch origin` перед каждым шагом.

### 1.2 Ветка `local/opencode` — код (только opencode пишет)

* opencode работает в ветке `local/opencode`, отведённой от `master` **или**
  от текущего tip `arena/…`, если нужны `AGENTS.md`/`collab/` (в `master` их
  нет). База указывается в шапке первого отчёта: `base: <sha>`.
* Arena **никогда не пишет** в `local/opencode`; она может её читать
  (`git fetch`, `git log`, `git diff`, `git show`).
* Так исключаются одновременные записи в один ref (это единственная
  реальная причина конфликтов).

### 1.3 `collab/` — доска сообщений (оба пишут)

Каталог `collab/` в ветке `arena/…` — единственное место, где разрешены
встречные записи. Каждая сторона пишет **только свои** файлы:

```
collab/
  PROTOCOL.md          # этот протокол (копия AGENTS.md в одну страницу)
  arena/               # пишет только Arena
    A-0001-<slug>.md   # задачи/ответы Arena
  opencode/            # пишет только opencode
    L-0001-<slug>.md   # задачи/ответы/логи opencode
  state.json           # «кто что взял» — обновляет только автор задачи
  runs/                # отчёты о прогонах в игре (пишет opencode)
    L-0001.json
```

* `A-…` = Arena → opencode, `L-…` = opencode → Arena.
* Номер монотонно растёт **внутри своего префикса**; коллизий нет, потому
  что префиксы разные.
* `state.json` правит **только автор задачи** (ставит `status`), исполнитель
  правит только поле `result_commit` в своей ветке и пишет отчёт файлом.
  Если это окажется неудобно — лучше вообще не трогать `state.json` и
  считать источником истины сами файлы.

## 2. Формат сообщения

Один файл = одна задача или один ответ. Шапка — YAML-подобная, чтобы её
можно было грепать:

```markdown
---
id: L-0007
from: opencode
to: arena
kind: task            # task | result | question | decision
status: open          # open | in_progress | done | blocked
branch: local/opencode
commit: 4f2a1c9        # для result: где смотреть
needs: A-0006          # на чём основано (необязательно)
game:                 # для result: где проверено
  build: 0.9.0
  locale: ru
  headset: Quest 3 / VDXR
---

## Задача
Одно-два предложения. Что должно измениться в поведении.

## Контекст
Ссылки на RVA/файлы, что уже известно. Не пересказывать `ru/ENCODING_NOTES.md`,
только ссылка на раздел.

## Критерий готовности
Проверяемое утверждение. «В VR на странице Options → VR подпись TURN MODE
показывает КИРИЛЛИЦУ „РЕЖИМ ПОВОРОТА“» — хорошо. «Работает» — плохо.

## Ограничения
Что нельзя делать (например: не менять `.exe`, не трогать ImGui-слой).
```

## 3. Как делить работу

Разделение — по **доступу к ресурсу**, а не по вкусу.

### Задачи, которые берёт Arena

* статический анализ DLL и `.lng`/`.bin` по дампам (`work/*.json`);
* написание/правка инструментов: `tools/apply_ru.py`, `charmap_codec.py`,
  анализаторы;
* правки перевода (`ru/strings.tsv`, `ru/ui2.json`) и их валидация;
* работа с кодировкой, charmap, форматом `.lng`, структурой PE;
* ревью диффов opencode (по `git show`), без запуска;
* документация: `ru/ENCODING_NOTES.md`, README.

### Задачи, которые берёт opencode

* всё, что требует **файлов игры**: `MetroExodus.exe`, `content*.vfs*`,
  `*.lng` из VFS, `MetroExodusVR.dll` из релиза;
* сборка патча (`tools/apply_ru.py --src … --out … --verify`) и запуск игры;
* **проверка в VR** и скриншоты/логи;
* добыча дампов для Arena: списки строк, xref-ы, содержимое `.rsrc`,
  распакованные ресурсы шрифтов, `user_vr.cfg`, лог мода;
* всё, что требует Windows-инструментов (dumpbin, IDA/Ghidra, exe-дамп).

### Правило одного владельца

У каждого файла ровно один владелец **на задачу** (а не навсегда): файл
переходит к тому, кто ведёт задачу, и это фиксируется в её шапке полем
`owns:`. Пока задача не закрыта, другой агент файл не правит — только
ревью через `git show`.

| Файл/каталог | Владелец |
| --- | --- |
| `tools/**`, `ru/strings.tsv`, `ru/ui2.json`, `ru/*.md`, `README.md` | Arena |
| `work/0.9.0/**`, `build/**`, `collab/runs/**`, `local/**` | opencode |
| `collab/arena/**` | Arena |
| `collab/opencode/**` | opencode |
| `collab/state.json` | автор задачи (см. §1.3) |

Если нужен файл из чужой зоны — не править, а **попросить** задачей.

Текущие передачи владения:

| Задача | Файл | Владелец | Что делает |
| --- | --- | --- | --- |
| `A-0003` | `tools/apply_ru.py` | opencode | `--fonts`, UTF-8-флаг, шрифтовая часть |
| `A-0003` | `tools/merge_cyrillic.py` | opencode | доноры, вливание кириллицы |
| `A-0003` | `ru/ENCODING_NOTES.md`, `docs/**` | Arena | модель, разделы 6–7, протокол |

## 4. Цикл работы (один круг)

```
Arena: A-NNNN (task)  ──push──▶  origin/arena/…
                                        │  fetch
opencode: читает задачу ──▶ делает в local/opencode ──▶ пишет L-NNNN (result)
                                        │  commit/push origin/local/opencode
Arena: fetch ──▶ читает L-NNNN + дифф ──▶ A-NNNN+1 (task/decision)
```

Правила, без которых цикл ломается:

1. **Перед каждой работой — `git fetch origin`.** Ветка могла уехать.
2. **Один коммит = одна задача.** В сообщении коммита — `Refs: A-NNNN`.
3. **Никаких `git push --force`** и никаких `git reset --hard` на чужой
   ветке. Если что-то не сходится — это `question`, а не force-push.
4. **Не переписывать чужие коммиты.** Только `merge`/`rebase` своей ветки
   на `origin/master`.
5. **Arena никогда не мержит в `master`** без явного «да» пользователя.
   opencode тоже.
6. Файлы в `collab/` — **append-only**: старые сообщения не редактируются,
   уточнение = новое сообщение с `needs:`.

## 5. Что Arena даёт opencode в готовом виде

Чтобы opencode не тратил контекст на разбор:

* `ru/ENCODING_NOTES.md` — карта кода, ответы на вопросы, варианты фикса;
* `work/xrefs.json`, `work/funcs.json`, `work/pe_analysis.json` — все
  строки, call-граф, все `lea/mov`-сайты (это позволяет искать по RVA без
  дизассемблера);
* `tools/*.py` — готовые скрипты (`disasm_func.py`, `xrefs.py`,
  `pe_xrefs.py`, `charmap_codec.py`, …), пути через `tools/re_paths.py` и
  переменные `METROEXODUSVR_DLL` / `METROEXODUS_EXE` / `METROEXODUS_GAME`.

## 6. Что opencode даёт Arena

* `work/*.json`-дампы, которых нет: `.rsrc` по именам, распакованные
  `fonts_*.bin`, `stable_us.lng`, список файлов VFS;
* `collab/runs/L-NNNN.json`: build, locale, что нажато, что видно, скриншот;
* прямые ответы на вопросы вида «какой шрифт у строки X» — это снимается
  только в игре.

## 7. Конфликты и тупики

* **Расхождение факта**: Arena говорит одно, в игре другое → приоритет у
  игры. opencode пишет `kind: decision`, Arena правит `ENCODING_NOTES.md`.
* **Задача невыполнима локально** (нет файла) → `status: blocked` и
  встречная задача с точным списком, что нужно с машины пользователя.
* **Обе стороны ждут** → через 1 круг любая сторона вправе сделать
  `question` с вариантами (A/B), а не молчать.
* **Пользователь — арбитр.** Всё, что меняет продуктовое решение (что
  переводим, что нет), решает он; агенты только готовят варианты.

## 8. Быстрый старт для opencode

```bash
git fetch origin
git log --oneline origin/arena/f1a57add-metroexodusvr -5
git show origin/arena/f1a57add-metroexodusvr:collab/state.json
git ls-tree -r --name-only origin/arena/f1a57add-metroexodusvr collab/
# взять самую свежую задачу для себя:
git show origin/arena/f1a57add-metroexodusvr:collab/arena/A-0001-*.md
```
