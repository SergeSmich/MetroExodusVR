# modkit — переключение билдов мода Metro Exodus VR 0.9.3

Система для прогонов «оригинал ↔ наш проект» в любом порядке без ручного копирования
файлов. Игровая папка всегда либо **vanilla**, либо один из профилей; всё, что убирается
из игры, уезжает в `work/modkit/archive/` (rename внутри тома, мгновенно, ничего не теряется).

## 1. Что где лежит

| Путь | Что это |
| --- | --- |
| `F:\SteamLibrary\steamapps\common\Metro Exodus` | игровая папка (цель). Игру не трогаем, только мод-файлы |
| `E:\MetroExodusVR` | чистая поставка мода 0.9.3 (стаб + `versions\0.9.3`), источник для профилей |
| `F:\Projects\MetroExodusVR\build\MetroExodusVR-0.9.3.dll` | наша сборка (перевод A/C, sha `a79ba15c…504ad`) |
| `work\modkit\profiles.json` | описание профилей `orig` и `ours` |
| `work\modkit\mod_switch.py` | сам переключатель |
| `work\modkit\installed.json` | что установлено сейчас (создаёт `apply`) |
| `work\modkit\archive\` | всё, что снято с игры (`manifest.json` внутри) |
| `work\modkit\runs\<id>\` | логи прогонов + `run.json` + `user_vr.cfg` |

Мод-файлы в игре (только они и удаляются):

```
MetroExodusVR.exe              стаб-запускалка
updater.json                   режим обновлений (всегда mode=never, pinned=0.9.3)
versions\0.9.3\                лаунчер, стаб, DLL, лицензии, logs, cache
logs\                          логи стаба
MetroExodusVR.exe.bak-*, updater.json.bak-*   старые бэкапы
```

Игра (`MetroExodus.exe`, `content_*.vfs*`, `patch_*.vfs*`) не затрагивается.
`%USERPROFILE%\Saved Games\Metro Exodus\<id>\user_vr.cfg` — настройки мода, остаются
на месте (vanilla их не читает); `collect` кладёт копию в прогон.

## 2. Команды

Все команды — из `F:\Projects\MetroExodusVR`, в PowerShell:

```powershell
$env:PYTHONIOENCODING='utf-8'; python -u -X utf8 work\modkit\mod_switch.py status
```

| Команда | Что делает |
| --- | --- |
| `status` | режим (vanilla/orig/ours), sha DLL, updater, свежие логи |
| `apply orig` / `apply ours` | снять текущий мод в архив и поставить профиль (требует закрытой игры) |
| `clean --yes` | убрать мод из игры в архив → vanilla (без `--yes` — предпросмотр) |
| `verify` | сверить DLL/стаб/updater с `installed.json`; код 2 = расхождение |
| `collect <id> --shots --note "..."` | забрать логи последнего прогона (+свежие скрины) в `runs\<id>\` |
| `purge` / `purge --yes` | показать/удалить архивы |
| `hashes` | sha256 профилей и установленной DLL |

`apply` сам проверяет: sha DLL после копирования, sha стаба, `version.json` = 0.9.3,
`updater.json` = `mode=never`. Если что-то не так — падает, не оставляя полуустановку молча.

## 3. План тестов

Цель: доказать, что наш билд не хуже оригинала и что правки перевода не ломают меню.

| Этап | Состояние | Что проверяем | Критерий |
| --- | --- | --- | --- |
| T0 | `clean` (vanilla) | Steam-запуск чистой игры | игра стартует, мода нет, VR-меню мода нет |
| T1 | `apply orig` | оригинальный мод 0.9.3 | меню и `SETTINGS → VR → GRAPHICS` открываются, интерфейс английский |
| T2 | `apply ours` | наш билд | то же меню по-русски: `НАСТРОЙКИ → VR → ГРАФИКА` открывается, кириллица без «квадратов» |
| T3 | `apply ours` (повтор) | стабильность | повтор T2 после перезапуска даёт тот же результат (не разовый) |

Порядок этапов произвольный: `apply` всегда начинает с чистого состояния, поэтому
T2 → T1 → T2 допустимо. Между T1 и T2 игру закрывать обязательно.

## 4. Инструкция одного прогона

1. **Поставить профиль** (игра закрыта):
   ```powershell
   python -u -X utf8 work\modkit\mod_switch.py apply orig   # или ours
   python -u -X utf8 work\modkit\mod_switch.py verify
   ```
   Ожидаемо: `всё на месте: orig` (или `ours`).
2. **Запустить игру** — ярлык/`MetroExodusVR.exe` в папке игры (не кнопка Steam: она
   запустит `MetroExodus.exe` без мода).
3. Когда появится окно «4A Engine» — **один клик внутрь окна**, чтобы оно было в фокусе.
   Дальше не переключаться на другие окна, окно не двигать.
4. Дождаться главного меню (≈20 с). Пройти: `НАСТРОЙКИ → VR`, открыть `ГРАФИКА`
   (в оригинале `SETTINGS → VR → GRAPHICS`), пролистать страницу.
5. Сделать скриншот экрана (PrintScreen или фото) — он пойдёт в отчёт.
6. **Выйти из игры штатно** (меню → выход). Не убивать процесс, пока не собраны логи.
7. **Собрать прогон** (до следующего `apply`, иначе логи уедут в архив):
   ```powershell
   python -u -X utf8 work\modkit\mod_switch.py collect T1-orig-graphics --shots --note "GRAPHICS открылся, UI английский"
   ```
8. **Проверить целостность**:
   ```powershell
   python -u -X utf8 work\modkit\mod_switch.py verify
   ```
   `FAIL` = стаб/updater подменили файлы → повторить `apply`, сообщить агенту.

Для vanilla (T0): `clean --yes`, затем запуск из Steam (`MetroExodus.exe`).

## 5. Что смотреть в каждом прогоне

- Меню вообще рисуется (не чёрный экран) и реагирует на мышь.
- Пункт `ГРАФИКА`/`GRAPHICS` **открывается** (это был баг с длиной строки).
- Остальные страницы VR-настроек тоже открываются (та же механика `mov r8d, imm`):
  `КОМФОРТ`, `УПРАВЛЕНИЕ`, `КАМЕРА`, `ИНТЕРФЕЙС` и т.д.
- Нет «квадратов»/обрезанных строк, значения списков читаемы (`СТЕРЕО`, `ВЫКЛ (TAA)`, `АВТО (K)`).
- В логе `runs\<id>\*_hook_*.log` нет новых `refused`/`error` (кроме известного
  `'mevr_reload_pouch' refused: lists need 2-255 printable ASCII labels`).

## 6. Ограничения и подводные камни

- **Нельзя `apply`/`clean` на запущенной игре** — скрипт откажется (файлы залочены).
- Стаб при старте проверяет GitHub. `mode=never` + `pinned=0.9.3` не дают обновиться,
  но `verify` после прогона — обязательная страховка: если DLL подменилась, `verify` даст `FAIL`.
- Логи мода пишутся в `versions\0.9.3\logs` и живут до следующего `apply` (уезжают в архив).
  Поэтому `collect` — сразу после выхода из игры.
- Запуск из фоновой команды агента игра не переживает (job object), плюс окно без фокуса.
  Запускает пользователь, агент только готовит профиль и читает результат.
- `purge --yes` стирает **все** архивы, включая старые логи 0.9.2 (≈2.5 ГБ). По умолчанию
  не удаляет ничего.

## 7. Откат

| Хочу | Команда |
| --- | --- |
| вернуть чистую игру | `clean --yes` |
| поставить оригинал | `apply orig` |
| поставить наш билд | `apply ours` |

| освободить место | `purge` (посмотреть) → `purge --yes` |
