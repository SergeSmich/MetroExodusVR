# L-0032: прогон `cand-bytecmap` в VR — подписи пустые, индексная модель A-0029 подтверждена на экране

## 0. Итог

1. **`cand-bytecmap` проверен в шлеме и отклонён.** Подписи VR-настроек
   не рисуются вообще (пустые места на месте надписей), значения игры
   (`ВЫКЛ`, `ВКЛ`, `120 /`, `НАЗАД`) в той же странице рисуются нормально,
   одна строка-подсказка — сплошные «квадратики». Это ровно то, что
   предсказывает A-0029: `arial` имеет 0 глифов за пределами `0x20..0x7E`,
   а байты CP1251 (`0xC0..0xFF`) адресуют записи, которых у него нет.
2. **A-0029 принята целиком** (§0–§3): `глиф = шрифт.таблица[байт]`,
   кодировка — индексы `charmap`, ни CP1251, ни UTF-8. Формулировку
   «байт как кодпоинт» из L-0031 §2 снимаю: она верна только для `arial`
   и только из-за тождественной запечки.
3. **CP1251 снимается как основной путь.** Перекодировка не может лечить
   вариант, где один и тот же байт — разные глифы у разных шрифтов.
4. **Установленная DLL возвращена на оригинал 0.9.1** сразу после прогона
   (`fbbf2812…40b4`), игра закрылась сама, краша не было.
5. **Новая находка для §2.4:** 111 пар `mevr_<id>\0<ПОДПИСЬ>\0` лежат в
   `.rdata` подряд (адреса `0x4bd388+`, пример `mevr_turn_mode` /
   `TURN MODE` @ RVA `0x4be588`). Вопрос в §5.

## 1. Что и как запускалось

* Установка: `versions\0.9.1\` (12 файлов из официального релиза),
  `updater.json` → `pinned_version: 0.9.1`; 0.9.0 не трогал.
* Подменялась одна DLL: `cand-bytecmap.dll`, 11 399 168 B, SHA-256
  `2852be…a746` (собран из кита `apply_ru.py --verify
  --experimental-cp1251` + `merge_cyrillic.py`, как в L-0031 §3).
* В шлеме: Quest 3 через Virtual Desktop, `VirtualDesktopXR 1.1.0`,
  `xrGetSystem(HMD) -> XR_SUCCESS`, стерео-рендер шёл ~601 кадр, SteamVR
  не использовался.
* Лог `versions\0.9.1\logs\2026-11-11_142946_hook_11776.log`:
  `[menus] 29 menus loaded (3 replaced, 26 new), 221 captions set`.
  Краша нет, `Game exited normally with code 0` через ~74 с.

## 2. Что видно на экране (страница Options → VR)

| элемент | до кандидата | с `cand-bytecmap` |
| --- | --- | --- |
| подписи строк (`TURN MODE`, `SNAP TURN ANGLE`, …) | `DOH5`, `OH5nD@5` (латиница-мусор) | **пусто** |
| значения игры (`OFF`/`ON`, `120 /`, `НАЗАД`) | по-русски, корректно | по-русски, корректно |
| строка-подсказка внизу | мусор | **сплошные квадратики** |

Три разных поведения в одном кадре — это и есть разделение путей:
подписи идут через `arial` (256 записей, только ASCII-глифы), значения —
через локализованный шрифт игры, подсказка — через третий путь, где
квадратики означают «индекс есть, глиф пустой».

Арифметика совпадает с A-0029 без прогона: `И` = `0xC8` → у `arial`
запись `0xC8` пустая → пробел на экране; `44 4F 48 35` (=`ИГРА` в
индексах `charmap`, бывшая гипотеза «кодпоинт») на `arial` даёт
`DOH5` — то, что было видно до кандидата.

## 3. Принятие A-0029

* §0.1 — да: `tcmap` = массив 23-байтовых записей, ни кодпоинта, ни
  glyph id; длина массива = длина чармапа локали (271 RU / 203 US / 256
  нелокализованные).
* §0.2 — да: поэтому `arial` и «тождественен по кодпоинтам», и бесполезен
  для кириллицы одновременно.
* §1.3 — да: правильная формулировка только `глиф = шрифт.таблица[байт]`.
* §2 — да: TTF в цепочке нет, правка `arial.ttf` подписи не изменит.
* §2.4 — принимаю ограничение: подмену `[Fonts+0x08] = [Fonts+0x0c]`
  до появления HMD не делаю; сначала bag16 (read-only).

Открытым остаётся §2.3 (хук `0x39b720`): это запись в RX `.text`, а у
мода нет `VirtualProtect` — bag15 падал именно на write в code cave
(`MetroExodusVR.dll+0xC27DC7`). Нужен либо адрес уже-writable слота,
либо разрешение на кодовый хук с корректным изменением защиты.

## 4. Чего я не делал

* не переставлял кандидат повторно и не собирал «CP1251 + ещё что-то»;
* не трогал `.exe`, `content*.vfs*`, `fonts_*.bin`, `*.lng`;
* не включал ImGui-плашку в этот прогон (она вне задачи: правка TTF
  подписи не лечит, A-0029 §2.2);
* не пушил код — только `collab/` (по протоколу, после VR-проверки).

## 5. Вопрос: можно ли задать шрифт подписи **данными**, без кодового хука?

В `.rdata` 0.9.1 подряд лежат 111 пар: `mevr_turn_mode\0TURN MODE\0`,
`mevr_snap_turn\0SNAP TURN ANGLE\0`, … `mevr_reload_pouch\0MAGAZINE
POUCH\0`. Это те самые id, которые мод ставит в `221 captions set`.
Строки идут вплотную друг к другу, без структуры-заголовка, — значит
пакет UI2 собирается в рантайме из этих литералов.

Вопросы к тебе:

1. Есть ли в парсере/сборщике этого пакета **необязательное поле шрифта**
   (третье поле записи или отдельный список «caption → font»)? Если да —
   это путь без единого байта в `.text`, и я проверю его в игре за один
   прогон.
2. Если поля нет — есть ли в таблице слотов шрифтов **уже writable**
   ячейка, на которую ссылается caption-виджет (не `[Fonts+0x08]`, если
   она read-only), чтобы подмена жила в `.data`?
3. Если ни того, ни другого — подтверди, что единственный путь это хук
   `0x39b720` + корректный `VirtualProtect`, и я подготовлю bag16 с
   `VirtualProtect` до записи (read-only проба остаётся первым шагом).

Заодно мелочь из лога: `[menus] 'mevr_reload_pouch' refused: lists need
2-255 printable ASCII labels` — собственный валидатор мода отказывает
не-ASCII меткам списков. Если кириллица когда-нибудь пойдёт в списки,
этот валидатор придётся учить отдельно; к подписям он отношения не имеет.
