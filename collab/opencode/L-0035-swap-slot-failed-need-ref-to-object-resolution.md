# L-0035: подмена слота `Fonts+0x08` (arial ← menu) кириллицу не даёт. Нужен путь «ref шрифта → объект»

## Задача

Опровергнуть или подтвердить, где в exe dword-ссылка из `Fonts` **резолвится в
объект шрифта** и где пустая ссылка превращается в `arial`; предложить
минимальный DLL-only патч, чтобы VR-страница Options → VR рисовала кириллицу.

## Контекст

### Что уже прогнано на 0.9.1 (full patch: `--strings kit091/ru/strings-0.9.1.tsv`,
180 строк, 18 stub)

| Прогон | Что делал | Что видно в VR |
|---|---|---|
| `--caption-all` | 259 caption-вызовов, 245 записей `font_name` (`set_ok=245`, `set_fail=0`) | те же ASCII-глифы (`nDLDEI;@?7<HD:IC53DI`) |
| `--caption-font menu` / `main_menu` / `nixie` | `font_name` = ref соответствующего шрифта | без изменений |
| `--swap-arial-slot` | cave один раз пишет `[Fonts+0x08] = [Fonts+0x0c]` | без изменений |
| без хука | — | без изменений |

Базовое наблюдение: на этой же странице **значения справа** (TURN MODE →
`<P573?`, `JCINc`, `BKJI`) тоже искажены identity-шрифтом, а `ESC НАЗАД` на
экране загрузки — нормальная кириллица. То есть проблема не в наших
caption'ах, а у всей VR-страницы Options: её контролы рисуются шрифтом без
кириллицы. Декод `swap2.png` через `ru/charmap.txt` даёт корректные фразы
(`ФИЗИЧЕСКОЕ ВРАЩЕНИЕ`), значит байты в буфере верные — не тот шрифт.

### Числа `--swap-arial-slot` (build `work/tmp-full091-swap2.dll`, SHA256 `3B80FE88…`)

* маркер: `+0x1C80 swap_done = 1`, `+0x1C84 old = 0x17056F20`,
  `+0x1C88 new = 0x001C58B0`; игра жива, скриншот `work/shots/swap2.png`;
* живое чтение `Fonts` (`exe+0x1733240`) сразу после: `+0x04: 0`,
  `+0x08: 0x17056E28`, `+0x0c: 0x001C58B0`, `+0x10: 0x001C58B0`.

Вывод: **реестр пересобран после нашей записи** — ref `menu` (`0x17056F20`)
стал `0x001C58B0`, а в слот arial вернулся новый ref `0x17056E28`. Однократная
запись в `.data` не держится; `Fonts::Fonts` (exe `0x39B5F0`) исполняется
повторно (кто и когда вызывает — не измерено, только факт пересборки).

### Факты по exe (0.9.1, RVA)

1. `Fonts` — не указатели на объекты, а 4 **интернированные ссылки** (dword):
   `idx = ref >> 24`, `off = ref & 0xffffff`, datum = `[intern_table + idx*8] + off`,
   refcount в `datum+8`. `Fonts::Fonts` (`0x39B5F0`) строит `regular`/`arial`/
   `menu`/`console` (длины имён 7/5/4/7) вызовами `0xAB20D0` и пишет в
   `+0x04/+0x08/+0x0c/+0x10`; синглтон-аксессор — `0x39B720`.
2. Литерал `arial` в exe **один** (file `0x1243D78`, rva `0x1245578`), и
   ссылка на него **одна**: `lea rdx, [rip+0xea9f2a]` в `Fonts::Fonts`
   (`exe 0x39B647`). Значит fallback «пустой ref → arial» идёт не через
   литерал, а внутри интернера/аксессора.
3. Сеттер свойств 0.9.1 — `0x9F0D0` (0.9.0 — `0x9BC70`): обходит записи по
   `0x98` байт от `[owner+0x38]` до `[owner+0x40]`, сравнивает `std::string`-имя
   (`+0x08`, len `+0x18`) и пишет значение через `std::string::assign`
   (`0x56340`) в `+0x60`. Это запись **свойства определения**, не поля живого
   контрола.
4. Лог мода: `[menus] Options menus cached 0.0 s after the first update` —
   инстансы кэшируются до первого показа, записи свойств приходят позже.

Код-кейв и сборка — `tools/caption_font_hook.py` (`--swap-arial-slot`,
`--self-test` PASS на всех комбинациях 0.9.0/0.9.1), драйвер —
`tools/apply_ru_091.py`. Диффы: `git show 369553e`, `git show da2ec8d` в
`local/opencode`.

## Вопрос

1. Где dword-ссылка из `Fonts` **резолвится в объект** для отрисовки контрола,
   и что делает код при `ref == 0`? Это и есть точка, где пустое значение
   становится `arial`. Нужны RVA резолвера и поле контрола, из которого он
   берёт ссылку.
2. Где шрифт **фиксируется в инстансе** контрола (копия/стиль/кэш при
   создании), чтобы понять, успевает ли `font_name` вообще и что перезаписать
   после кэша.
3. Какой минимальный **DLL-only** патч вы предлагаете: (а) писать ref `menu` в
   поле шрифта живого инстанса после создания, (б) хук точки резолва,
   (в) третье. Нужны конкретный RVA/смещение и что именно писать.

## Критерий готовности

В VR на странице Options → VR подпись `TURN MODE` и значения справа
отображаются кириллицей, а не `nDLDEI;@?7<HD:IC53DI`; скриншот `swap3.png`
совпадает с `full091_menu_font.png` по расположению, но с русскими глифами.
Игра не падает, в логе нет `refused:` у наших меню.
