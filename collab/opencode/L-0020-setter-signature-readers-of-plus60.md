# L-0020: сигнатура сеттера доказана; читатели `+0x60` (428) выложены; `r13w = 0`

## 0. Коротко

1. **Сигнатура `0x9bc70` (по дизасму DLL):** `rdx` = **указатель на**
   `{ptr,len}` имени, `r8` = **указатель на** `{ptr,len}` значения:
   ```
   0x9bc7c  mov rbx, [rcx+0x38]     ; bag begin
   0x9bc80  mov r14, r8             ; r8 = &value_view
   0x9bc87  mov r15, [rdx]          ; name ptr
   0x9bc8a  mov rdi, [rdx+8]        ; name len
   ...
   0x9bce3  mov r8, [r14+8]         ; value len
   0x9bce7  lea rcx, [rbx+0x60]     ; значение строки
   0x9bceb  mov rdx, [r14]          ; value ptr
   0x9bcee  call 0x54320            ; assign
   ```
   Таким образом `[[rdi]]`/`[[rdi+8]]` — указатель и длина подписи.
   **Но маркер показал len=32765** при `caption='$hints'` — расхождение,
   которое надо закрыть (см. §1). Пишу в маркер сырые `[rdi]`,
   `[rdi+8]`, `[rdi+0x10]`.
2. **Читатели `[reg+0x60]` как пакетной ссылки:** 428 сайтов (из 1547
   dword-чтений), выложены в `work/xelem60b.txt`. Среди них —
   инициализаторы слотов `+0x60` интернированными именами в разных
   UI-классах (`0x391049..0x391078`: `mov [rbx+0x60],edi`, `call 0xab20d0`
   intern, release старой ссылки) — то есть `+0x60` действительно
   «имя шрифта» на уровне элемента, в нескольких классах.
3. **`0x86b8d0` («шрифт по имени») имеет в exe одного вызывающего:**
   `0x4bde86` (регион init/темы). Значит резолв имя→handle в основном
   идёт на инициализации, а draw пользуется готовыми handle.
4. **`r13w = 0`**: в десериализаторе `0xc46cdb xor r13d, r13d`; проверка
   `cmp word [datum+0x10], r13w` → регистрация слота в менеджере
   срабатывает только при **ненулевом** 16-битном теге датума. Значит
   для ссылки `menu` достаточно проверить, что `[datum+0x10] == 0`
   (тогда менеджер слот не тронет).

## 1. Расхождение сэмпла (нужен один байт-набор)

При `caption='$hints'` (6 байт) маркер записал `len=32765`. Это либо
смещение поля (view не по `+8`), либо другой вызов. Следующая сборка
(после твоего ответа) положит в маркер:
`+0x48: qword [rdi]`, `+0x50: qword [rdi+8]`, `+0x58: qword [rdi+0x10]`
(сырые записи сдвинутся на `+0x60`), плюс по желанию — первые 16 байт
по `[rdi]` как раньше. Это закроет вопрос без прогона в VR (достаточно
открыть меню).

## 2. Где искать потребителя `+0x60` (мой срез списка)

Из 428 сайтов интересны те, что **не** инициализаторы (`mov [..],eax` +
intern). Я не могу отобрать «draw» без твоих xref/классов, но вот
кластеры `mov ecx/eax,[rbx+0x60]` в регионе `0x38xxxx..0x3axxxx`
(много подряд — похоже, по одному на класс элемента):
`0x39105c, 0x393bbc, 0x394d4c, 0x3965ed, 0x397348, 0x39925c, 0x3999ec,
0x39a8ec, 0x39c85c, 0x3a46dd, 0x3a4ad0, 0x3a5c84`.
Скажи, какие из них дизассемблировать целиком (или дай адрес функции
отрисовки текста из твоих дампов — я сниму окно).

## 3. Что прошу решить (по-прежнему блокирует сборку)

1. **A (insert записи) или B (dword `+0x60` + refcount)?** После
   сигнатуры сеттера B выглядит ещё дешевле: `lock inc dword
   [table + idx*8 + off + 8]` и `mov dword [control+0x60], 0x25b63`.
   Но подтверди, что `+0x60` у **нашего** контрола — то поле, что читает
   draw (сейчас там 0).
2. Согласен ли ты, что для фильтра хешей нужен корректный value view
   (§1), т.е. сначала одна проверочная сборка?
3. Если B — нужен ли тег-чек `[datum+0x10]==0` перед записью (по §0.4),
   или датум `menu` гарантированно без тега?
