# Отказ `mevr_reload_pouch` — НЕ дефект перевода

## Симптом
```
[menus] 'mevr_reload_pouch' refused: lists need 2-255 printable ASCII labels
[menus] mevr_weapons: a row refers to a refused setting   (x2)
```

## Что проверено
1. Сообщение печатается из функции мода `0xAA7F0` (0.9.3), единственная ссылка на строку —
   `lea rcx,[rip+…]` по RVA `0xAA99B` → строка по RVA `0x4F29B0`.
2. Перед сообщением две проверки:
   - `0xAA870…0xAA87A`: `lea rax,[rbx-2]; cmp rax,0xfd; ja` — количество меток списка
     должно быть **2..255** (0 и 1 отвергаются);
   - `0xAA898…0xAA8B9`: длина метки 1..127 и каждый байт printable ASCII
     (`sub cl,0x20; cmp cl,0x5e; ja`), сайт `0xAA8B6`.
3. В наших сборках `cmp cl,0x5e` расширен до `cmp cl,0xff` (`tools/apply_ru_093.py`,
   `ADDRS["validators"]`, `--validators`). Проверено побайтово в `work/tmp/audit_cand.dll`
   и `build/MetroExodusVR-0.9.3.dll`: `80 f9 ff`.
4. Патч гейта работает: в том же прогоне зарегистрировано **130 settings**, отказ только
   у pouch, хотя метки других списков переведены и содержат байты ≥0x80
   (`WEAPON FLICK` → МЯГКО / ОБЫЧНО / СИЛЬНО). Значит printable-гейт открыт.
5. Отказ воспроизводится на **чистом оригинале** DLL автора
   sha256 `2f9ed2d1…458b2c64` (логи `work/modkit/archive/2026-11-18_125421-before-ours/…/logs/2026-11-18_125323_hook_3888.log`
   и `…2026-11-18_185018-before-ours/…/logs/2026-11-18_184943_hook_18584.log`).

## Вывод
`mevr_reload_pouch` имеет в моде **одну** метку (`HIP`) → не проходит проверку «2..255».
Это дефект самого мода 0.9.3, не зависящий от локализации. В меню VR просто нет
пункта «MAGAZINE POUCH»; строка `HIP` → «НА БЕДРЕ» при этом нигде не используется.
Чинить патчем логики мода не нужно; упомянуть в письме автору (вариант C).

## Побочный итог
Гипотеза «гейт printable-ASCII не переехал» закрыта: один из трёх сайтов
(`0xAA8B6`) — именно он, и он расширен. Остальные два — `0xAAE05` (captions страницы,
«page declared twice») и `0xAC6E5` (caption опции списка) — тоже расширены.
